Glossary

Every lesson uses these words exactly. Repo-wide terms also live in the root GLOSSARY.md.

Term Meaning in TravelBliss
Authentication Answering who are you? Done once per request by SessionService.authenticate. [OWASP]
Authorization Answering what may you do? Done per field by @Authorized and the authChecker. Always after authentication.
Access token The short-lived string the API issues at sign-in. The web app sends it on every request as Authorization: Bearer <token>.
Bearer token A token anyone holding it can use, with no further proof. [RFC 6750 §1.2] The access token is one.
JWT (JSON Web Token) The access token's format: header.payload.signature, each part base64url. [RFC 7519 §3]
Claim One fact in the payload: userId, iat (issued at), exp (expires). Readable by anyone.
Signature HMAC of header + payload with the secret. Any edit, or another secret, makes it fail to verify.
Secret (API_SECRET_JWT) Key only the API holds. Needed to mint a valid token, not to read one.
Refresh token Long-lived token whose only job is getting new access tokens. Kept in the travelBliss_rf cookie and in Redis; only with Remember Me. [RFC 6749 §1.5]
Rotation Every refresh spends the refresh token and issues a new one, so each works once.
Reuse detection A spent refresh token presented again means a copy exists: revoke all of that user's refresh tokens.
HttpOnly Cookie attribute: JavaScript cannot read the cookie; the browser still sends it.
SameSite Cookie attribute controlling cross-site sending: Lax locally, None (+ Secure) in production.
useSession() The web app's only view of the session: { user, signIn, signOut, isSigningIn }.
Session link createSessionLink: adds the Bearer header to every request and, on UNAUTHENTICATED, refreshes once and resends.
Blacklist Redis keys blacklist:<access token> written at sign-out, so that token makes a guest until it expires.
Valid-from Per-user time in Redis before which every token of that user is revoked; set on password change (#115).
Idle timeout A remembered session ends 30 days after its last refresh (API_REFRESH_EXPIRED).
Absolute timeout No session outlives 90 days from sign-in (API_SESSION_MAX_AGE, via auth_time; #116).
Signed-in user The User a request acts as: ctx.auth.user on the API, useSession().user on the web.
Guest A caller with no valid session: ctx.auth is undefined.
Role USER or ADMIN, stored on the user. Only checked when a decorator lists roles.
Context (ctx) Per-request object every resolver receives: { req, res, auth }. Built before any field runs.
@Authorized type-graphql decorator that guards a field. Empty means any signed-in user; with roles, one of those roles.
authChecker Our function type-graphql calls for each guarded field. Returns true or false; never touches the database.
UNAUTHENTICATED Error code for a guest on any guarded field: we don't know who you are.
UNAUTHORIZED Error code for a known caller missing the role a field requires. (Before #115 also sent to guests on role-gated fields.)
Linked sign-in A way to sign in as a user through an outside provider, such as Google or Facebook, instead of a password. A user can have several, alongside a password or without one. One linked_sign_in row each. Avoid: social login.
Provider The outside site (Google, Facebook, or the local DEV fake) that vouches for who the person is.
Authorization code The one-time value a provider puts in the callback URL; only the API, with its secret and the PKCE verifier, can trade it for a profile. [RFC 6749 §4.1]
Callback GET /auth/<provider>/callback: where the provider sends the browser back.
State Random value made at the start of a trip, stored in Redis and in the travelBliss_ls cookie, and checked on the callback. Binds the trip to the browser that started it. [RFC 6749 §10.12]
PKCE (code verifier) A secret the API keeps for the trip; its hash goes to the provider first, the secret itself with the code. A stolen code alone is useless. [RFC 7636]
Provider user id The provider's permanent id for the person (Google's sub). The only thing a linked sign-in is matched on; never the email. [OIDC §5.7]
Connect / disconnect Adding or removing a linked sign-in for the signed-in user, from the account page.
