The refresh token

Access token Refresh token
Lifetime 5 min (API_JWT_EXPIRED) 30 days idle, at most 90 days from sign-in; cookie, token and Redis key expire together (#116)
Secret API_SECRET_JWT API_SECRET_REFRESH
Browser keeps it in page memory cookie travelBliss_rf: HttpOnly, AES-encrypted
Server keeps blacklist entry after sign-out Redis refreshToken:<userId>:<token>, expiring at exp
Exists only if signed in signed in with Remember Me (hasRefresh)

Cookie attributes

Attribute Local Production Why
HttpOnly yes yes no JavaScript (or injected script) can read it
Secure no yes HTTPS only; required by SameSite=None
SameSite Lax None production web app and API may be on different sites
Expires the token's exp browser drops the cookie when the server stops accepting it (was a separate 30-day Max-Age)

Refresh, step by step

  1. cookie missing or won't decrypt → INVALID_COOKIES
  2. token fails verify(…, API_SECRET_REFRESH) → INVALID_TOKEN
  3. user deleted → USER_NOT_FOUND
  4. DEL refreshToken:<userId>:<token> (atomic; returns keys removed)
  5. removed 1 → rotate: new access + refresh token, new key, new cookie
  6. removed 0 → reuse: delete every refreshToken:<userId>:* → INVALID_TOKEN

Stolen cookie: whichever of you and the attacker refreshes second trips reuse detection, and every remembered session of that user ends.
