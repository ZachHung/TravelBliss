The request pipeline

1 · AuthenticateSessionService.authenticate(header) → ctx.auth or guest
→
2 · Authorize@Authorized → authChecker(ctx, roles)
→
3 · Resolveresolver runs, reads ctx.auth.user

Stop 1: who becomes a guest

Header / token Result
missing, or not Bearer … guest
forged or expired guest
on the logout blacklist guest
user deleted guest
valid ctx.auth = { user, token, exp } (one database read)

Stop 2: the decision table

Field Guest USER ADMIN
no decorator (login, register) data data data
@Authorized() (me, logout) UNAUTHENTICATED data data
@Authorized(Role.ADMIN) (allUser) UNAUTHENTICATED UNAUTHORIZED data

The code describes the caller: a guest is always UNAUTHENTICATED (our checker throws); a known caller missing the role is UNAUTHORIZED. Before #115 a guest on a role-gated field got UNAUTHORIZED, because type-graphql picks the error by whether roles are listed. Both arrive with HTTP 200 in errors[].extensions.code.
